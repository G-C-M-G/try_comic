## 二、改代码前必须知道的不变量

这五条是全流水线的地基，违反任何一条都会产生“看起来能用但产物悄悄变坏”的回归：

1. **蓝框 = 原子单位 + 用户意图**。蓝框是不可分割的 OCR 最小单位，蓝框之外的一切
   保持原样（不 OCR、不翻译、不擦字、不嵌字）。“无蓝框页整页保持原图”是特性不是缺陷。
2. **岛外零改动是结构保证**。擦字只拷贝掩膜内像素，任何越界由双像素审计兜底抛异常
   （`island_erasure.py`）。别为了“修一下边缘”放开这个约束。
3. **无框岛绝不进 OCR**。manga-ocr 没有检测能力，纯色/无关区域会幻觉出文本。
4. **缓存签名绑定一切输入**。原文 SHA + 模型 + 术语表 + prompt 版本 + 上下文。
   **改翻译 prompt 必须升 `PROMPT_VERSION`**（`translator.py`），否则旧缓存静默命中、
   你以为改了其实没改。分组规则变了则删 `dataset/*/islands.json` 按新规则重建。
5. **run.json / run.log 是 GUI 的唯一进度通道**（原子写、tmp+rename）。
   子进程 stdout 只进日志，GUI 不解析 stdout——别往反方向做。

## 三、关键决策与踩坑结论

### 3.1 采集与蓝框

- **默认采集已换成 PaddleOCR 全页检测**；Photos 蓝框路径保留为 `--box-source photos`。
- **Photos 2026 的扫描文本视图会对非文字区整体加暗**。蓝框判定必须以扫描文本帧为基准，
  否则期望蓝整体偏亮、匹配率会大幅下降。
- 悬停显示的“扫描文本”按钮有两层坑：光标停在按钮上会把按钮抓进帧里；`invoke()` 后
  焦点留在按钮上，后续 Ctrl+A 不生效。对策是鼠标挪开 + 标题栏点击移焦（best-effort）。
- **UI 自动化的时序参数不要写死**：scan-wait / scan-settle / select-wait / regrab-wait /
  focus-clear-pct 全部做成 CLI + GUI 可调。Photos 更新或换机器时只调参，不改代码。
- **IME 全角标点**：输入法敲 “4，6” 会把全角逗号混进页码，静默匹配不到任何页。
  四个 CLI 入口统一在切分前归一化。CLI 参数要按“人怎么打字”设计容错。
- **UI 自动化失败要大声**：三次 Ctrl+A 仍无蓝色像素 → `selection_review_required`
  硬规则阻断下游，宁可人工确认也不悄悄跳过。

### 3.2 读字（OCR）

- **当前主力：manga-ocr 读字，Paddle 负责检测/交叉验证**。Paddle 的检测很好用，
  但文本识别实测很弱（尤其竖排手绘字），不能当主读。
- **AI OCR 是可选通道**（`--stage2-engine ai-ocr`），按框付费。实测后已撤下默认位置：
  每本新书数百次付费调用，质量提升集中在少数场景，性价比不够。
- **读数缓存必须记录引擎出处**。否则同一份缓存里可能混着本地引擎和付费视觉模型的读数，
  事后分不出哪条是谁读的。换引擎时应整本重读一次。
- **AI 的说明性输出会被当成读数**。视觉模型读不到字时会回“图片中没有任何日文文本…”；
  这类输出必须过滤成空读数，否则会一路翻译、嵌字。
- **“宁少不编”的提示词会把“读不全”引导成“少读/拒读”**。手绘/风格化竖排上尤其明显；
  若将来重新启用 AI OCR，这两条提示词要先改。
- 读字层的天花板在**手绘/风格化竖排**；这类样本上本地 manga-ocr 通常比视觉模型更稳。

### 3.3 翻译与术语

- **AI 整页批量优先，本地 Sakura 兜底**。跨页上下文只给“上一页原文”，不给译文：
  上限 12 条 / 400 字，既保连续性又不破坏按页并行。
- **缓存签名绑定**：源文 SHA + 模型 + 术语表 SHA + prompt 版本 + 上下文。
  改翻译 prompt 必须升 `PROMPT_VERSION`；改缓存格式必须升 `FORMAT_VERSION`。
- **拟声词自动回灌术语库**：只有短假名/符号、译文短且不在疑问词黑名单、同一译法至少
  出现 2 次才收录；同一原文出现第二种译法就撤出；用户手写条目只读不写。
- **功能词护栏**：`の`、`は`、`が` 这类助词如果被当成拟声收进术语库，会污染几乎每个岛
  的提示词。用 fugashi 词性拒收整条都是助詞/助動詞/補助記号/接続詞的条目。
- **不要硬卡译文字数上限**。实测模型本来就在压缩（中位约为原文的七成），硬卡只会逼它
  丢原意。提示词写“以原文为准、通常压到七成、宁短勿长”，不写死数字。
- **符号字体回退**：`msyh.ttc` 没有 ♡/♥ 等字形，PIL 会渲染成豆腐块 □。按字符取字体
  （`_FontChain` → `seguisym.ttf`）；判定缺字形不能用“非零像素数 > 0”，因为豆腐块本身
  也是非零像素。回退逻辑必须在**每个绘制分支**都走一遍。

### 3.4 擦字与排版

- **岛外零改动**：擦字只拷贝掩膜内像素，双像素审计负责越界抛异常。
- **LaMa 擦字已接入**：`--erase-inpainter {auto,lama,fsr}`，默认 auto；LaMa 不可用时
  自动退回 FSR。LaMa 在 CPU 上比 FSR 慢 4~6 倍；像素完整性契约有测试锁住。
- **“过大单框”判据必须配绝对下限**：只按“1.5× 同方向基准”判，在小字页面上会退化成
  “人人超标”。现用“1.5× 基准 + 页短边 8% 下限”。凡是相对基准的倍数阈值，都要配一条
  绝对下限——这条在采集期筛框时已经踩过一次。
- **整页字号上限**：逐岛“各自撑满”会让同页字号出现 2 倍级差。加“≤ 1.5 × 该页蓝框
  短边中位数”的整页上限，只封顶不放大。
- **放不下的岛保留原图**：嵌字前先做一次布局预排（只算不画，输入与真正嵌字一致）；
  判定为 rendered and clipped 的岛从擦字与嵌字集合里剔除。否则会出现“擦白框 + 一个
  看不见的小点”，比保留原文更差。
- **改分组规则后 dataset 不会自动重建**：`islands.json` 比 `capture.json` 新时会跳过。
  改规则要删 `dataset/*/islands.json` + `selection_blocks.json`，不要用 `--overwrite`
  （它会把译文与读数缓存一起清掉）。

### 3.5 拟声/手绘字过滤

- **几何判据分不开“拟声”与“无气泡对白”**。有些漫画家不把对白放进气泡，而是直接画在
  画面上。按“不是气泡 ⇒ 不是台词”会把这批要翻译的句子一起吃掉，所以 `--drop-art-boxes`
  默认关，判据与实现保留。
- **“丢” = 该岛保留日文原样**（不擦、不译、不嵌），不是台词消失。这个口径是后面所有
  成本判断的前提：误杀台词的真实代价是“这句以日文留在画面”。
- **严格联合版**：`(P<0.6 ∨ 框级软标记) ∧ 字数<7` 才留日文。任何 ≥7 字的岛结构上不可能
  被留日文（不依赖模型可靠度）；短叹留日文属于口径内可接受。框级软标记 = 1.2× 基准
  且 > 5% 页短边；5~6 字的被标记岛强制进复核 CSV。
- **实测否决的路线**（都不要再投入）：
  - 概率救援：同一把尺子复核，约 92% 被标记的拟声又被捞回。
  - 环带上下文特征：曲线抬高 25~55%，但没有改变操作点。
  - 气泡检测器：严格拟声 F1 低于视觉判据；`TEXT_FREE` 命中的岛里大多数是“该翻译”的。
  - 通用拟声保留词典：整岛聚合后严格拟声召回约 0.013，任何词汇查表机制都难生效。
  - 字符级规则：最好命中约 45% 拟声，同时误伤真词（如叠词），是更糟的静默错误。
- **人工清单是安全网**：force-keep / force-drop 清单 + 复核 CSV 优先于自动判据；
  两个调用点都读，重跑 typeset 不会把救回的岛又丢掉。

### 3.6 缓存、并发与运行

- **OCR 读数缓存**按页/框存，只存非空读数；任何重跑（重分组/重嵌字/重合并 PDF）
  都跳过 OCR，识别零成本。
- **翻译缓存**分岛级与页级批量；缓存键包含上下文与术语表 SHA。缓存跨页共享，
  同文本不同上下文不会误命中。
- **并发**：翻译/嵌字默认 3 路并行（硬封顶 3）；AI OCR 默认 12 路、护栏 32，
  撞 429 就调小；并行采集有 auto-fit。
- **dataset 复用要检查规则版本**：`islands.json` 比 `capture.json` 新就复用，但必须检查
  新规则需要的字段（如 `bg_flat_ratio`、`soft_flag_version`）；缺字段就重建。
- **`--overwrite` 是“先删后重建”**：清空前会写 `*.bak`，失败时按日志回滚；同一个书目录
  不能并发跑两个 `--overwrite`（会互相清空/重建同一批产物）。
- **`--images` 指错目录**：指到 `outputs/oneclick/{书名}` 时应明确提示“这看起来是输出
  目录”，而不是只报 `no images found`。
- **原子写**：PNG/JSON 一律临时文件 + 原子替换；文件被占用时报“关掉占用它的程序”，
  不要报成误导性的 invalid argument。

## 四、当前债务（按危险排序）

1. **明文 API key**：`config/api_keys.json`（git-ignored，历史干净）。长期建议改环境变量
   或 Windows 凭据管理器。
2. **`photos_capture.py` 体量与静默异常**：4100+ 行、38 处宽泛 `except`（部分静默
   `pass`）；print 与 run.log 双轨并存。UI 自动化排障最缺“当时它到底看到了什么”。
   方向：统一 logging + 文件 handler，静默 except 至少落 debug 日志。
3. **打包 exe 依赖源码树**：exe 运行时会回调仓库 venv 的 python（`_venv_python()`
   缺失时报错，而不是把 exe 自己当解释器）。要么接受“exe + 源码树”的分发形态，
   要么把采集/OCR 打进包里（工程量大）。
4. **测试盲区**：GUI 交互、`windows_ocr.py`、`paddle_ocr_worker.py`、PDF 端到端无测试；
   translator / ai_ocr 的 HTTP 层已有 mock 测试。
5. **opencv 双装**：venv 里同时装了 opencv-python 4.11 与 opencv-contrib-python 5.0，
   而 `requirements.txt` 写的是 contrib-headless <5。重装环境时以 contrib 为准
   （xphoto/FSR 擦字依赖它），建议清掉多余的那个。
6. **AI OCR 的性价比仍未闭环**：若要重新启用，可只对“无假名且含拉丁”的框送视觉模型
   （约 2.5% 的框），而不是全量。
7. **拟声过滤仍有盲区**：正常字号的短拟声、碎片化文本靠复核清单兜底；再往上需要更多
   标签或重训。

# Windows Photos OCR 自动化实现

更新时间：2026-08-03

## 当前状态

原型边界已于 2026-08-03 被 `photos_capture.py` 和 `photos_translate.py` 取代。
现在程序会真正调用 Windows“照片”的“扫描文本”，不使用 MangaOCR 生成文字或坐标：

```text
打开原图 -> 定位照片窗口 -> 自动切换扫描文本
  -> 检测照片的白描边 OCR 覆盖层
  -> 逐列点击并复制照片识别文字
  -> 检测蓝色选区并映射到原图坐标
  -> Ctrl+A 获取照片完整列清单，核对采集数量
  -> 面板排序/按标点合句 -> Sakura 翻译
  -> 气泡文字擦除后嵌字；画面文字白描边覆盖
```

运行完整自动流程：

```powershell
venv\Scripts\python.exe photos_translate.py "原图.jpg" "译图.jpg"
```

运行中不要操作鼠标和键盘。程序会自动处理照片当前已经开启 OCR 的情况；如果逐列采集少于
照片“全选”清单，会直接报错而不生成残缺译图。输出旁会保存 `*.photos.json` OCR 清单和
`*.state.json` 翻译/渲染记录，其中 `backend` 必须为 `Windows Photos Scan Text`。

## 数据边界

Windows“照片”的左右键选择单位是**一列文字**，不是完整句子或完整气泡。因此不能逐列直接翻译。正确的数据流是：

```text
逐列选择与复制
  -> 保存每列文字、选中顺序和高亮矩形
  -> 映射到原图坐标
  -> 按气泡/文本容器聚合相邻列
  -> 组内按日文竖排从右到左排序，并按列尾标点切分整句
  -> 整句翻译
  -> 保留每列多边形，供擦字和嵌字使用
```

`photos_ocr.py` 仍保留为清单归一化和人工校准工具。自动路径由以下两个文件负责：

- `photos_capture.py`：照片窗口控制、白描边文字岛检测、逐列复制、蓝色选区坐标和完整性校验；
- `photos_translate.py`：面板/句子组合、翻译、气泡擦字、普通嵌字与白描边覆盖。

`photos_ocr.py` 实现界面之外的辅助部分：

- 列级 OCR 清单校验；
- 照片窗口高亮矩形到原图像素坐标的映射；
- 显式气泡编号优先、几何关系兜底的多列合句；
- 输出兼容现有状态思路的 `source_segments` 和 `lines`；
- 明确跳过被标为 `ruby`、`sfx` 或 `ignore` 的列。

## 清单格式

最小输入示例：

```json
{
  "source": {
    "path": "C:/path/5.jpg",
    "width": 985,
    "height": 1400
  },
  "capture": {
    "app": "Windows Photos",
    "image_viewport": [120, 40, 613, 740]
  },
  "columns": [
    {
      "id": "column_001",
      "text": "探知できている",
      "display_bbox": [420, 80, 440, 190],
      "selection_order": 0,
      "direction": "vertical",
      "container_id": "bubble_001",
      "break_after": false,
      "role": "text"
    }
  ]
}
```

运行：

```powershell
venv\Scripts\python.exe photos_ocr.py capture.json
```

输出的 `capture.normalized.json` 同时保留列级数据和合并后的翻译区域。`regions[].text` 才是翻译输入；`regions[].source_segments` 是后续精准覆盖所需的列级几何，不能丢弃。

## 自动化限制

照片应用目前不会通过复制操作给出坐标，`OcrControl` 也没有公开 UI Automation
`TextPattern`。因此坐标从当前蓝色选区的画面差分测量，程序同时记录：

- 照片窗口位置和缩放；
- 原图在窗口内的实际显示矩形 `image_viewport`，不能包含黑边或工具栏；
- 每次点击文字列后的蓝色选区矩形和复制文字；
- 原图宽高。

窗口移动和缩放不需要人工标定：每次采集都会读取 `OcrControl` 的实时视口并重新映射。
照片大版本若改变覆盖层颜色或控件 ID，采集器会因完整性核对失败而停止，需要更新适配器。

## 分组原则

1. 优先使用气泡/白色文本容器检测得到的 `container_id`。同一容器中的多列按右到左合并。
2. 没有容器编号时，只合并水平距离近、纵向重叠足够、列宽相近的竖排列。
3. 仅靠几何合并的多列区域会标记 `needs_review: true`，避免把相邻的两个气泡误并。
4. 小号振假名和拟声词必须保留在列清单中，但用 `role` 排除在对白翻译之外，便于复核误过滤。
5. 同一气泡可能包含多句。默认遇到列尾 `。！？` 时结束一句；漏标点时可给该列设置 `break_after: true`。

## `5.jpg` 实测

原文：`C:\Users\YLP\Desktop\软件\漫画翻译\原文\54话生肉福利连\5.jpg`

配对译文：`C:\Users\YLP\Desktop\软件\漫画翻译\翻译\葬送的芙莉莲漫画_第54话 对比\5.jpg`

Windows“照片”对页面中间大气泡逐列复制的结果为：

```text
探知できている
複製体の総数が
受験者よりも
僅かに少ないです。

特に一番の脅威である
ゼンゼさんの複製体の
反応が見つかりません。
```

因此该气泡是七个列级框、两个句级翻译单元。照片识别正确给出了 `ゼンゼ`，优于当前管线曾出现的 `ゼノゼ`。配对译文也明确把它分成两句，说明“列级采集、句级翻译、列级几何保留”是合理边界。

本页已用原图和“照片”截图的图像特征完成显示区域标定：RANSAC 仿射估计得到 281 个内点，显示比例约为 `0.523122`，原图四角落在窗口的 `[106.78, 47.35, 544.28, 675.21]`。七列高亮的实测窗口矩形和映射结果保存在 `samples/photos_ocr_page5_excerpt.json`。

在当前“照片”版本中，鼠标点击列后复制是稳定的；自动化发送左右键没有稳定切换到相邻列。因此原型不依赖左右键完成遍历，下一阶段优先验证高亮颜色提取、气泡容器分割和点击式列枚举，再决定是否启用键盘快速路径。
